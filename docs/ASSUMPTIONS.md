# Assumptions and boundaries

## What a finding means

- `pth_executable_line`: an exact leading `import ` or `import\t` line in a `.pth` file under a recognized site directory. **Not a malware verdict.**
- `startup_entry_point`: a `.start` entry-point declaration. Applicable to Python 3.15+; its inclusion is legitimate in many packages.
- `customize_module`: a `sitecustomize.py` or `usercustomize.py` candidate, with unverified import precedence.
- `known_sha256`: bytes matched a source-attributed IOC supplied to the tool.
- `imported_module_*`: a bounded, syntax-only inspection of a directly resolved module found an API call pattern. It is not a data-flow analysis.

The scanner explicitly distinguishes candidate presence, version-specific configuration, and observed execution. It **never** labels an artifact a proven malware infection by filename alone.

## Confidence boundary

For snapshots, only recognized `site-packages` and `dist-packages` directories are treated as `.pth` or `.start` configuration locations. Customize modules are inventoried elsewhere, but their importability is **unknown** without a complete, process-specific `sys.path`. `pyvenv.cfg` is parsed statically. System-site inheritance, application-directory precedence, `. _pth` files, `PYTHONPATH`, loader behavior, exotic importers, .so extension modules, and multiple Python interpreters are not fully modeled.

For wheels, the tool analyzes candidate install destinations from the wheel specification. No claim is made that the wheel was installed or executed. Hashes in `RECORD` are a consistency check; `RECORD` can be regenerated by a malicious package publisher and is not a provenance guarantee.

A direct `import name` is resolved only against files visible under the relevant site directory or `.pth`-added directories in the inspected snapshot. An unresolved import may still resolve from the Python standard library or another runtime path. A resolved import does not prove it ran. A static AST signal in a module does not prove the call was reached.

`.start` behavior is based on Python 3.15 documentation; this project does not execute foreign Python code. Specify `--python-version` when the target version is known. Without it, startup status is a candidate assessment.

## Safety properties

- Scanned Python source is read as bytes and parsed with `ast` where useful; no `eval`, import, subprocess, or interpreter execution of target material.
- POSIX snapshot reads use directory-relative `open` with `O_NOFOLLOW` to block symlink traversal. Platform fallback performs component checks but is not immune to adversarial, concurrent filesystem mutation. Prefer immutable snapshots.
- Wheel members are never extracted. Absolute paths, traversal segments, duplicate paths, and archive symlinks are excluded. Size and member-count limits prevent routine oversized-archive processing, but resource use still depends on the trusted analysis host.
- Reports are created outside snapshot roots, with restrictive temporary permissions and atomic replacement. HTML content is escaped and has a restrictive CSP.
- Optional source-line output may expose sensitive data; it is disabled by default.

## Severity policy

| Severity | Meaning |
|---|---|
| `high` | Hash matches a supplied, source-attributed IOC. Requires contextual triage. |
| `medium` | Potential startup-executed code or a static execution/network API pattern. |
| `low` | Customize candidate or format/decoding concern. |
| `info` | Inventory-only path, inactive version case, or other context. |

These priorities are **triage convenience**, not probabilities of malware, and are not validated detection rates.

## Release-specific coverage

The 1.1.0 audit records untraversed symlink directories as coverage issues. Symlinked site directories and external directory links make the scan incomplete; an internal alias to a physically scanned ordinary directory is reported without claiming missing coverage. Parent package `__init__.py` candidates are inspected statically when a dotted import is present; this is not a complete import execution trace. Wheel `RECORD` checks cover startup candidates rather than the entire wheel.
